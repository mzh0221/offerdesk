# 用户视角体验检查

检查日期：2026-11-09；检查对象：当前 OfferDesk 1.1.2 源码，Mac 本机 Electron 窗口。

结论：核心的收集、预填、保存、查看与投递管理流程能够完成。应先解决输入保护和草稿恢复，再调整小窗口与核对表单，最后优化入口与操作反馈。

下文保留最初检查时的问题与建议。后续改进已落实到当前源码，实施与验证结果见文末。所有检查使用独立临时数据目录。

## 实际复现的问题

### 1. 高优先级：录入内容在误关闭后丢失

- 操作：文字录入 → 粘贴招聘原文 → 按 Esc → 再次文字录入。
- 结果：原文变为空白；关闭前没有提示。
- 操作：原文预填 → 人工修正公司名、填写招聘链接 → Esc → 继续上次导入。
- 结果：公司名回到预填值，招聘链接为空。用户刚完成的核对工作没有保留。
- 原因位置：`components/add-job.tsx:78` 的草稿保存只在特定操作触发；输入变化和关闭未保存；招聘链接未进入草稿保存与恢复逻辑。
- 建议：本地草稿覆盖原文、截图、核对字段和招聘链接，输入停止后自动保存；显示“草稿已保存”。关闭时若仍有未保存内容，提供“保存草稿 / 放弃 / 继续编辑”。纯手动填写也需要保护。
- 验收：修改后关闭并恢复，所有字段一致；保存失败时保留当前输入并说明原因。

### 2. 高优先级：应用重启后找不到未完成草稿

- 操作：粘贴招聘文字 → 预填 → 关闭录入框 → 确认“继续上次导入”可见 → 完全退出 → 重新启动。
- 结果：恢复入口从 1 个变为 0 个；IndexedDB 中仍存在 1 条未保存的导入草稿。
- 原因位置：`components/dashboard.tsx:40`、`components/add-job.tsx:82`；入口依赖 sessionStorage，启动时没有查找本地未完成草稿。
- 建议：从 IndexedDB 恢复草稿入口，并允许明确丢弃草稿；如允许连续开始多次导入，应能列出各条草稿，而非只保存一个指针。
- 验收：完全退出、重开后仍能继续；丢弃草稿时同步处理其关联附件，不影响已保存岗位。

### 3. 高优先级：详情编辑没有离开保护

- 操作：打开岗位详情 → 修改个人备注 → 按 Esc → 再次打开。
- 结果：备注恢复为空，没有提示。代码中的关闭按钮、遮罩点击也没有未保存检查。
- 原因位置：`components/job-detail.tsx:63`、`components/dialog.tsx`。
- 建议：统一显示“有未保存修改”；点击关闭、遮罩或 Esc 时，提供“保存并关闭 / 放弃修改 / 继续编辑”。未改动时可直接关闭。
- 验收：备注、状态、日期、岗位信息都受保护；保存后关闭不重复询问。

### 4. 中优先级：最小桌面窗口下，跟进入口被挤到右侧

- 操作：将真实桌面窗口调整为允许的最小尺寸 760 × 560。
- 结果：表格可视宽度 710px，内容宽度 940px；需要横向滚动才能完整访问右侧状态和操作，投递日期列隐藏。
- 原因位置：`desktop/main.cjs` 最小宽度为 760px；`desktop/renderer/styles.css` 的卡片断点为 720px，因此正常缩小桌面窗口无法进入卡片布局。
- 建议：在桌面可达到的宽度内切换卡片或精简列表，优先保留岗位、状态和详情入口；如果保留横向表格，固定关键列并明确提示可横向滚动。
- 验收：760 × 560 下无需横向滚动即可打开详情、更新状态；筛选、新增及保存入口可见。

## 界面与交互改进建议

以下为依据界面和操作流程提出的改进建议，不等同于程序故障。

### 5. 核对表单过长，对照原文费力

当前核对表单一次展开公司、岗位、薪资、学历、毕业年份、实习时长、到岗条件和多个长文本框；招聘原文位于底部的折叠区域，保存按钮也在内容末尾。填写链接时，需要继续向下滚动才能找到保存按钮。

建议先呈现公司、岗位、地点、薪资与链接，将其他条件分组；宽窗口采用左侧原文/截图、右侧表单，窄窗口提供方便切换的原文面板。底部固定“返回”和“保存岗位”，必填与选填说明应明确；预填为空不应被说成“原文未说明”，可用“未提取，请核对”。

相关位置：`components/add-job.tsx`、`components/job-form.tsx`、`desktop/renderer/styles.css`。

### 6. 同样是修改投递状态，保存规则不同

列表中的状态选择会立即保存并提示成功，详情中的状态、日期、备注需要点击“保存修改”。用户可能沿用列表中的操作习惯，改完详情状态就关闭。

建议保留清楚、一致的保存反馈；若详情继续采用手动保存，应始终显示未保存状态，并和第 3 项的关闭保护一起处理。保存按钮只在有修改时启用；“收起编辑”应明确只是收起表单，并提供独立的取消修改操作。

相关位置：`components/dashboard.tsx:updateStatus`、`components/job-detail.tsx`。

### 7. 手动录入入口不够直接

首页主要提供“上传岗位截图”和“文字录入”，空白列表也只引导上传截图。只想填写公司、岗位的用户，需要先打开导入框，再找到“手动填写”。

建议用“新增岗位”统一承载截图、文字、手动三种方式，或在现有入口旁补充清晰的“手动录入”；空白列表同时呈现几种可用方式，说明“仅公司和岗位必填”。保持首次启动为空白，不加入演示记录。

相关位置：`components/dashboard.tsx`、`components/add-job.tsx`。

### 8. 多张截图识别后的操作可以更省力

现有流程支持离线识别、重试、人工编辑和预填，但重试成功的新文字需要用户自行复制到识别原文。截图较多时，用户还需要自己对应各张图片的识别结果。

建议每张截图展示识别状态并允许单独重试；对新增文字提供“插入原文”操作，保留已修改内容；识别完成后突出下一步“核对岗位信息”。恢复草稿中的截图也应能够继续排序、移除或补充，保持与首次录入一致。

相关位置：`components/add-job.tsx`。真实复杂招聘截图的准确率没有在本次专项中测量。

## 建议实施顺序

1. 输入保护：完整草稿保存、重启恢复、详情离开保护。
2. 核心布局：760px 桌面适配、核对表单分组、固定保存按钮、便捷对照原文。
3. 操作一致性：状态保存反馈、手动入口、识别结果合并和恢复截图编辑。

这些改进均可保持现有单人、本机、离线存储架构。若后续希望增加排序、面试安排或状态历史，应作为独立需求讨论，不列为本轮必做项。

## 改进实施结果（2026-11-09）

- 草稿在停止输入 500ms 后自动保存，包括原文、核对字段、招聘链接、录入步骤、补识别文字与截图；纯手动录入同样受保护。草稿写入串行执行，失败时保留界面输入，不以失败内容替换已有附件。
- 首页从 IndexedDB 读取全部未完成草稿，可选择继续或明确丢弃。丢弃草稿及附件使用单个事务，已保存为岗位的导入不可丢弃。旧格式草稿无需迁移即可恢复。
- 录入框关闭时，尚未保存的内容可保存为草稿、放弃或继续编辑；详情增加修改标记、保存并关闭、放弃和取消修改。原生窗口关闭或重载也有未保存保护。
- 1050px 及以下桌面窗口使用岗位卡片；760 × 560 下可以直接更新状态、查看详情和新增岗位，不需要横向滚动。
- 核对表单分为基本信息和可折叠的选填条件，招聘链接提前展示；宽窗口并排展示原文与表单，窄窗口将原文放在上方。核对保存栏固定在底部。
- 首页与空白列表提供直接手动录入入口；详情明确手动保存规则，无改动时保存按钮禁用。打开新界面时清除上一步的提示，避免遮挡表单。
- 截图展示逐图识别状态、失败后可单独重试；补识别文字可一键插入，保留人工修改；恢复的截图支持排序、移除和补充。修改截图也保留已有原文，下次覆盖识别前仍需确认。
- 恢复截图直接从 IndexedDB 读取 File，避免通过 fetch 读取 blob URL 被 CSP 拦截；没有放宽 CSP 或页面权限。
- 键盘焦点范围排除隐藏控件，支持折叠区标题；关闭确认出现时，将键盘焦点限制在确认操作内。

最终验证：46 项单元测试、类型检查、生产构建、8 项桌面回归全部通过；检查宽屏核对页和最小窗口截图。新增回归包含旧格式草稿、多个草稿的选择/丢弃、保存失败、详情未保存保护、原生重载取消、恢复截图编辑与最小窗口操作；原有真实离线 OCR 场景增加了单图重试和一键合并文字验证。

本轮没有重新制作安装包，也没有执行 Windows 实机验证；应用身份、来源、数据库名与对象仓库保持原样。新增草稿属性为可选字段，兼容已有记录。
